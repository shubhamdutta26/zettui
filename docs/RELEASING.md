# Releasing

Use the current [release checklist](RELEASE-CHECKLIST-0.7.15.md) before tagging. Preserve pending COSMIC and physical multi-computer validation caveats if still untested. Update the package version in Cargo.toml and the matching local package in Cargo.lock; verify with `cargo check --locked` without changing unrelated dependencies. Finalize the changelog and roadmap for the approved milestone. Run the checks in [Development](DEVELOPMENT.md). Commit, rebase onto main, merge, and push. Wait for successful CI on the exact release commit, then create an annotated `vX.Y.Z` tag and push it. The tag triggers the Linux release workflow; it verifies the manifest version and generates the portable x86-64 archive, Debian and RPM packages, Arch PKGBUILD and checksums. Verify workflow success and download/check assets before announcing the release.

Local packaging requires a static musl binary, binutils and optional dpkg-deb/rpmbuild. Run `bash scripts/package-linux.sh target/x86_64-unknown-linux-musl/release/zettui X.Y.Z`. Outputs are in `dist/`; verify with `(cd dist && sha256sum -c SHA256SUMS)`. The config example is installed as documentation, never as a user's live configuration. Packages include README, license and the example configuration, not the full `docs/` tree; consult the repository at the corresponding release tag for the complete guides.

CI also tests packaging before tagging (pull requests, main, or manual workflow runs). Run `bash scripts/verify-linux-packages.sh X.Y.Z` after packaging to verify checksums, package metadata and the extracted tar/Debian/RPM binaries without installing them. Use `--available` only for local checks when a package tool is absent. Native Arch builds and interactive behavior are manual checks.
